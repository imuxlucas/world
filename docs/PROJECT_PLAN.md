## 已确认的首版边界

两天后开对齐会，讲解约 15 分钟。首版只交付一个精修微缩景观、三个可点击主体和各自的 OKR 详情弹窗。模型独立保存与配置；完整资产管理页面、拖拽 GUI、AI 导览、Jev 演示和额外可玩设施会后再做。以下长期架构服务于后续扩展，不构成会议版交付负担。

## 1. 项目要达成什么

为 OKR 对齐会准备一个个人表达鲜明、便于现场讲述的网站。观众进入一个完整的未来游乐场，通过三个标志性实体认识 Lucas 的三个工作方向；点击实体后，能迅速读懂目标、关键结果、行动和预期产出。

成功标准：第一眼能识别三个主角；点击后能说明“为什么做、打算做到什么、如何验证”；看完后能记住 Lucas 对设计、代码和 AI 的个人判断。

暂用新名称：Code × Craft、业务 × Link、AI-Native × Workflow。原工程的稳定 ID 保留：Craft 对应 o3，Link 对应 o2，Workflow 对应 o1。展示顺序与原始编号分别管理，不自动重新编号。

周期已确认：名义为 2026 H2，实际执行窗口为 10—12 月。统一从 period 配置读取，页面标题用“2026 H2”，副标用“执行窗口：10—12 月”。会议在两天后，桌面演示 15 分钟为首要场景。

## 2. 已有材料告诉我们什么

- Drama 本地工程是 krpano 全景、热点、部分 3D 对象与 HTML 弹窗的组合。值得延续的是“在场景中发现内容—点实体—读详情—回到原位置”的节奏，完整实时 3D 并非该体验成立的前提。新站采用实时主体，是为了后续摆放、动画和资产管理。
- okr-park 已有完整 3 O × 3 KR、权重、说明、产出和部分流程。真正缺少的是实体与工作方向的语义对应、真实视觉材料，以及更清晰的讲述层级。
- 旧内容全部 progress=null。5 个 AI 组件、2 次分享、1—2 个移动端亮点是目标值，不能展示成已完成成绩；50/40/10 等是精力或 KR 权重，不能画成完成进度。
- 当前三张内容主图明确是视觉占位。对齐会可使用真实问题截图、计划流程图、已有 demo 或目标交付示意，不要求把尚未完成的计划包装成成果。
- 旧工程已有 feature-building.glb、狗、装饰物与心形几何，后续逐项评估是否符合新场景。参考资产数量不等于最终场景需要全部使用。
- Blender 当前选中的是双层圆环 / 碟状建筑，具有明显的径向结构。可优先检查并整理已有几何，再决定是否需要图生 3D；目前仅观察了视窗，未验证拓扑、材质或与旧 GLB 的对应关系。

## 3. 统一美术方向

工作概念：**一座由设计判断驱动的未来游乐场。** 可用 BUILD MY WORLD 作为概念图工作标题，正式命名稍后确定。

把用户喜欢的审美转化为不同的设计职责：

| 参考偏好 | 在本项目中的作用 |
| --- | --- |
| aespa 的 AI 与先锋感 | 异形建筑、精确金属结构、现实中不可能存在的设施比例 |
| Hearts2Hearts 的千禧与心形 | 心形负空间、半透明树脂、局部糖果色、俏皮的观看方式 |
| ILLIT 的梦核 | 安静的无人乐园、柔和远景、日常设施与超现实尺度之间的轻微错位 |
| IVE 的华丽与自我欣赏 | 精心取景的主角视角、珠宝般的局部反光、自信的个人署名 |

基础材质建议为拉丝或抛光银、珍珠白烤漆、冰蓝玻璃；粉色用于心形和少量内部发光，深蓝灰用于结构与文字。少量青柠色可作为 Craft 的代码状态色。三座设施共享材质库、光照与细节尺度，通过轮廓、运动和局部点色区分。

心形承担空间或交互功能：例如 Link 摩天轮轮毂中的镂空心形、两段步道围出的心形空地、观察窗口中的心形裁切。首轮选一到两种作为主要母题。已有 FOCUS 参考图里“透过心形纸洞观看”的方式很适合转译为窥视窗口。

质感制作顺序：构图和轮廓 → 比例 → 材质粗糙度与反射环境 → 接触阴影 → 微小动画 → 后期效果。统一浏览器中的光照、曝光和色彩；概念图中生成的高光不能直接视为模型已经具备同等质感。

## 4. 三个主体的建议映射

| 目标 | 实体 | 形式与运动 | 对内容的解释 |
| --- | --- | --- | --- |
| Code × Craft | 精密环形展馆 / Craft Pavilion | 参考已选双环建筑，等距骨架、对齐的接缝、可读代码刻字；悬停时构造线短暂显现并归位 | 将设计判断落实为精确实现；三处展示位承接代表作、AI 组件、个人表达 |
| 业务 × Link | 心形摩天轮 / Link Wheel | 多个不同形态的舱体连接同一轮毂；相同的灯光节奏沿各舱传递；心形作为轮毂负空间 | 平台、APP、生成工具拥有各自场景，同时遵循一致体验规则；三个 KR 仍在详情中完整呈现 |
| AI-Native × Workflow | 流程旋转木马 / Workflow Carousel | 一枚小型载体沿环形轨道经过输入、Build、验证和复用站点，输出有状态变化 | 表达有输入、有验证、有复用的迭代；三个 KR 对应输入判断、快速 Build、团队复用 |

这是首轮隐喻建议。旋转木马可以保留经典顶棚和升降节奏，承载物可选抽象工具胶囊或精修的小马；在概念阶段比较后确定。流程阶段的数量不必强行等于 KR 数量。

三主体以三角构图落在同一个场地。摩天轮位于后侧形成竖向轮廓，环形展馆与旋转木马位于前侧两端，以屏幕面积而非真实高度平衡视觉权重。中央留出视线与步道空间。

开场采用稍俯视的透视镜头，三主体同时可见。先限制旋转和缩放范围，让主构图稳定；每个主体设独立聚焦镜头。自由漫游可以后置。

## 5. 内容与交互一起设计

首版页面结构：一个场景入口 `/` + 三个目标弹窗，目标支持通过 URL hash 定位即可。三个弹窗共用排版和交互组件，用内容区分。完整的制作资产库 `/studio/assets` 与资产详情 `/studio/assets/:assetId` 放到会后，具体路由届时确定。

主交互：浏览场景 → 悬停显示目标名称与一句话 → 点击实体或对应文字入口 → 短镜头过渡 + HTML 详情 → 关闭回到原镜头。首次点击主体即可看到完整 O 的概览，不需要先找到小型 KR 热点。

目标详情的首屏同时给出：目标原文、一句话主张、三个 KR 的短标题与关键目标值。继续阅读每个 KR 时展示具体行动、验收方式、里程碑、预计产出与相关示例。存在真实当前状态时再加入基线和进度。

建议为三个 O 分别准备一个讲述锚点：

- Craft：一个交互组件或作品 demo，配“我做了什么设计判断”；5 个 AI 组件作为计划目标。
- Link：一张完整创作链路图，把多端不一致的具体问题与目标体验并列；标出计划验证的 1—2 个移动亮点。
- Workflow：一条真实任务从需求到 demo 的流程图，标出断点、拟改变的步骤和验证办法；2 次分享作为计划目标。

文字使用 HTML 排版，保留复制、键盘操作和清晰阅读。场景中的代码或标牌由程序生成清晰纹理或文字，不让图生模型负责准确拼写。

会议功能进入首版：直接切换三个 O、返回全景、暂停动态、目标总览入口。不增加背景音乐制作任务。键盘与触屏入口共享同一内容；关闭详情后恢复焦点与镜头。窄屏采用静态场景入口，正文按屏幕宽度正常排版。

15 分钟建议分配：1 分钟介绍个人主张与乐园，三个 O 各 4 分钟，最后 2 分钟说明执行优先级、需要的协同与希望对齐的事项。每个 O 的三条 KR 在一个弹窗内完整呈现，避免现场多层跳转。

## 6. 调整后的资产制作链路

**内容骨架与实体隐喻 → 整场概念图 → 三张单体设计卡 → 简模构图 → 一件资产完整小样 → 批量制作与验收 → 网页组装。**

整场概念图用于决定画面，不直接作为整个公园的图生 3D 输入。每张单体设计卡要展示完整轮廓、比例、材质、正侧背视角与需运动部件，保持几何一致并去除遮挡。给生成服务时按实际支持方式提交单体视图，避免让拼贴图被识别为多个对象。

采用混合制作：异形外壳、心形雕塑等可试 Rodin 或 Tripo；摩天轮轮轴、等距舱体、轨道、径向骨架等精确结构用 Blender 或程序化建模。已有可用建筑优先整理复用。

按动画拆件：摩天轮分支架、轮体、舱体及各自轴心；旋转木马分底座、顶棚、转盘、载体及运动路径；Craft 展馆分主体结构、玻璃、标牌与可动构件。自动分件可以辅助，但部件正确性、父子层级和旋转轴要人工验收。

先选择一个供应商完成代表性小样，依据轮廓、材质、清理成本和浏览器效果决定是否继续或切换。首版不同时建设两套完整生成平台。

API 在制作阶段运行：本地脚本或后端提交、保存任务状态、查询、下载。保存生成参数和原始产物；网页直接加载验收后的本地静态资产。密钥不进入前端，会议播放不等待模型生成。

第一件精修小样建议选 Craft 展馆：它有已有建筑参考，同时能验证金属、玻璃、精确结构和内容弹窗。如果源模型清理成本过高，再选一个心形舱体完成图生 3D 对照小样。

## 7. 模型资产管理与后续 GUI

三个层次独立保存，以稳定 ID 关联：

| 层次 | 保存什么 |
| --- | --- |
| content / objectives | O、KR、周期、目标值、权重、行动、验收、媒体与 demo |
| assets / manifest | 资产 ID、版本、来源、源文件、网页 GLB、材质、节点、动画、尺寸、缩略图、制作状态 |
| scene / layout | 实例 ID、资产 ID、对应 O、位置、旋转、缩放、点击范围、聚焦镜头、标签锚点 |

同一资产可以有多个场景实例，换模型不会改写 OKR 文案。资产本身不绑定某个唯一 O，具体关联放在场景实例中，资产详情可反查使用情况。

首版先用最小独立预览场景验收模型，不建设管理后台。会后再补每件资产的独立预览页：转台预览、统一的最终光照预设、部件与动画开关、尺寸、面数、文件体积、纹理信息、来源、版本、关联场景、点击范围。资产预览页服务于制作管理；观众点实体打开的是 OKR 详情，两者职责不同。

统一约定：制作源文件与网页文件分开；明确单位、朝向、地面基点和节点命名；应用变换；显式记录移动部件的 pivot；发布前检查法线、UV、材质、阴影、压缩后的外观和交互命中。

后续 GUI 基于同一 scene layout 接入移动、旋转、缩放控件，增加撤销、重置和 JSON 导入导出。首版只预留数据结构；不提前建设复杂编辑器、账户或数据库。

推荐落地目录：

```text
lucas-okr-world/
  docs/                   # 方案、视觉规则、内容清单
  design/                 # 概念图、单体卡、页面稿
  asset-sources/          # 原始产物、Blender 源文件，不进入网页构建
  scripts/                # 生成任务与资产处理脚本
  public/assets/          # 验收后的 GLB、纹理、缩略图
  src/content/            # OKR 与周期
  src/assets/             # 资产清单
  src/scene/              # 场景布局、灯光、镜头与交互
  src/ui/                 # OKR 弹窗、导览、静态入口
  src/studio/             # 独立资产预览与后续布局 GUI
```

技术栈可延续 Vite + React + TypeScript + Three.js / React Three Fiber + Drei。沿用已验证的内容、状态和弹窗可达性思路；新工程重新组织场景、美术和数据。依赖版本在初始化时统一选择，不直接照抄旧项目的全部依赖。

## 8. 阶段与验收

| 阶段 | 可审阅产物 | 进入下一步的标准 |
| --- | --- | --- |
| A 内容与概念 | 三个 O 的一句话、9 KR 内容表、参考职责分工 | 周期与目标值含义明确，每个 O 有讲述锚点 |
| B 视觉设计 | 一张主场景图、三张单体卡、一张真实内容弹窗稿 | 三个主角清楚，构图、材质、心形用法统一，正文能读 |
| C 浏览器小样 | 简模全景 + 一件精修资产 + 对应真实弹窗 | 页面里也有预期质感；点击、聚焦、返回和加载成立 |
| D 完整组装 | 三主体、少量辅景、9 KR、三个内容弹窗 | 设施含义能讲清，目标与产出对应，不出现占位主图 |
| E 会议打磨 | 演示模式、窄屏策略、静态入口、设备实测 | 完整讲解不卡流程，故障时仍能读内容 |
| F 会后增强 | 完整资产管理页、布局 GUI、可选 Jev 工作流演示 | 不影响已稳定的内容与场景 |

先把一个关键镜头、一件模型和一个内容弹窗做成能代表最终质量的小样，再扩展。阶段 A 与 B 可并行推进。两天内按以下顺序推进，避免把时间都花在资产生成上：

- 第一天前段：锁定主场景概念图、三个实体轮廓与内容弹窗排版；用现有 9 KR 排出可读内容。概念阶段最多一轮明显方向调整，先锁镜头、构图和材质。
- 第一天后段：搭好浏览器中的三主体简模、光照与一个精修主体；三个实体均能打开各自弹窗。当天结束必须有可讲述的完整交互版本。
- 第二天前段：完善剩余主体，统一材质与阴影，放入少量必要辅景；精修内容信息层级。模型制作和弹窗工作可并行。
- 第二天后段：冻结主体造型，按 15 分钟脚本走读，处理加载、点击、返回和投屏字号；准备静态场景入口并在实际展示浏览器检查。

若图生模型反复不能满足轮廓或分件要求，及时使用既有建筑与程序化规则结构完成首版。若完整三维辅景成本过高，远景采用静态背景，三个核心主体继续保持实时点击。压缩范围时优先减少装饰与复杂动画，保住三主体质感和完整内容。

首轮工程预算建议，需按实际展示设备调整：三个核心资产各约 3—8 MB，首屏关键资源总量争取 20 MB 内，纹理以 1K/2K 为起点；桌面以稳定 60 fps 为目标，必要时降低阴影、像素比和透明层。文件体积不能代替 GPU 实测，还需记录三角面、绘制次数、纹理占用和帧时间。

展示网站不依赖图生服务在线返回。准备静态场景图 + 同一套 HTML 目标内容作为降级方案；模型加载失败不阻止读取 OKR。首次进入优先加载三主体与基础环境，装饰和高开销效果后置。

## 9. 外部参考的准确用途

- [carousel-circular-3d](https://github.com/ddevkim/carousel-circular-3d)：React 环形图片轮播与 lightbox，可以借鉴作品图集交互；不是可放进沙盘的旋转木马机械模型。
- [TypeSafe Jev 发布文章](https://typesafe.ai/blog/introducing-system-one-models-and-jev)：结构化决策模型，可选用于 Workflow 展项中“输入状态—选择下一步”的演示。它不生成 3D、拆分资产或渲染场景。首版普通点击交互无需依赖它。
- [Hyper3D Rodin API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5)：图生模型、GLB、PBR 与面数设置。[Bang](https://docs.hyper3d.ai/en/api-specification/bang) 提供分件能力；动画结构仍需验证。
- [Tripo 图生模型](https://developers.tripo3d.ai/en/docs/generation-image-to-model/p)、[多视图](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/p)、[分件](https://developers.tripo3d.ai/en/docs/mesh-segment)：可作为另一条单资产制作路线，不能将 API 能力直接视为最终美术质量保证。
- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[TransformControls](https://threejs.org/docs/pages/TransformControls.html)：资产加载与后续变换编辑的基础。
- [小红书摩天轮参考](https://xhslink.cn/o/2MseTvIvQ7t)：本轮网页抓取未能读取内容，因此未据此假定视频中的具体实现或教程流程。
